# Desktop shell (spec 017, `packages/desktop`)

- Layout: pure, Electron-free modules in `src/main/` (`probe`, `backoff`, `daemonProcess`, `shell`, `permissionWatcher`, `navigation`, `errorPage`, `trayIcon`, `daemonEntry`) tested with Vitest; only `main.ts` and `src/preload/index.ts` import `electron`. `scripts/build.mjs` bundles both to CommonJS (`dist/main.cjs`, `dist/preload.cjs`, `electron` external, shared+zod inlined). Electron loads `main` with require, so no ESM.
- **Electron binary install**: with pnpm 9 the `electron` postinstall did not download the binary on `pnpm install` here (no `dist/`, no `path.txt`); run `node node_modules/electron/install.js` once (it uses `~/.cache/electron`). pnpm 10+ needs `onlyBuiltDependencies: [electron]`.
- **Wayland host crash**: on this machine Electron 44 defaults to Wayland and dies with SIGSEGV right at startup ("--ozone-platform=wayland is not compatible with Vulkan"). `--ozone-platform=x11` (XWayland) works. The Playwright smoke tests pass it on Linux; the app code does not force it. `--no-sandbox` is needed in dev because `chrome-sandbox` is not setuid. When running by hand under `timeout`, the "GPU process launch failed ... Goodbye" lines are just the kill, not a bug.
- **utilityProcess** has no useful command line (`electron --type=utility ...`), so find the daemon pid with `ss -ltnpH 'sport = :PORT'`, not `pgrep -f`.
- `utilityProcess.fork(<cli bin .mjs>, ['start','--no-open','--port',N], {stdio:'pipe'})` runs the cli bin (top-level await and ESM work); `child.kill()` is SIGTERM and the daemon exits cleanly. Quit = `before-quit` preventDefault -> `controller.stop()` -> `app.quit()`.
- Playwright Electron (`_electron.launch({args:[appDir, flags], env})`) works with Playwright 1.64 + Electron 44; do not pass `CLAUDE*` env into the app. `app.evaluate(({app}) => app.quit())` drives the same path as the tray "Sair".
- Single instance: tests isolate the lock with `AGENTS_OFFICE_USER_DATA` (applied via `app.setPath('userData')` before the lock). A second `electron` with the same userData exits 0 and fires `second-instance`.
- The main process also connects to `/stream?role=ui` (global `WebSocket` of Electron's Node) so notifications work with the window hidden. Side effect: the daemon always sees a UI client while the app runs, so reloading the window no longer releases pending permission requests (hooks stay held, cards come back via `permission.snapshot`).
- Daemon health recognition: `/health` must have `ok:true`, string `version`, numeric `sessions` and `agents`; any other HTTP answer or a silent listener = "port busy"; ECONNREFUSED = free. After a child exit the port is probed again (it may now belong to another agents-office or program) before restarting.
- Daemon entry: `AGENTS_OFFICE_DAEMON_ENTRY` > packaged `resources/daemon/bin/agents-office.mjs` (spec 019 must ship it with its node_modules) > `packages/cli/bin` if `dist/cli.mjs` exists > `packages/daemon/bin` (tsx).
- Tray icon is drawn at runtime (`renderTrayIcon`, BGRA bitmap, gold dot when requests are pending), no image assets.

## Hooks management from the UI (spec 018)
- `src/main/hooksService.ts` imports the daemon's `settings-merger` by relative path (`../../../daemon/src/cli/settings-merger`); esbuild inlines it and no dependency was added. The CLI and the UI therefore share the exact merger (uninstall is byte-identical, backup `.agents-office.bak` once).
- Hook command written by the app: `ELECTRON_RUN_AS_NODE=1 "<app exe>" <daemon entry>/agents-office.mjs hook [--port n]` (Claude runs hooks via `sh -c`; no `node`/`npx` needed). `--port` only when not 4777. Windows has no env prefix syntax, so it falls back to `node`. The `agents-office.mjs hook` tail keeps the merger marker working. Verified in e2e by running the written command and seeing `hooksSeenAt` update.
- IPC: channels in `src/main/hooksChannels.ts`; `src/preload/bridge.ts` (`createHooksBridge(invoke)`) is pure and unit-tested with a mock `invoke`; main validates `event.sender === window.webContents` and the frame origin (`isTrustedSender`). The types live in `@agents-office/shared` (`desktopHooks.ts`).
- Settings path override for tests/e2e: `AGENTS_OFFICE_SETTINGS_PATH` (plus a temp `HOME`); never point tests at the real `~/.claude/settings.json`.
- Web: DOM overlay (`ui/settingsPanel.ts`, pure logic in `ui/settingsLogic.ts`) mounted only when `window.agentsOfficeDesktop.hooks` exists; first-run notice remembered in `localStorage` (`agents-office.hooksPrompt.dismissed`). Web e2e (plain browser) is unaffected. The desktop e2e needs `packages/web/dist` built (`pnpm build`).

## Packaging and desktop e2e (spec 019)
- `pnpm --filter @agents-office/desktop dist` = workspace `pnpm build` -> `scripts/stage-daemon.mjs` -> `electron-builder --config electron-builder.yml`. Works here (Linux, online): AppImage + deb in `packages/desktop/release/` (gitignored, with `build/`), ~100-125 MB each. electron-builder downloads Electron, the appimage tool and fpm on first use (needs network).
- The daemon is shipped as `resources/daemon` (= `pnpm --filter agents-office deploy --prod` output, staged in `build/daemon`), outside the asar. **electron-builder never copies `node_modules` via extraResources** (even with an explicit filter), so `scripts/after-pack.cjs` copies it. Copy with `verbatimSymlinks: true`: `cpSync(..., {dereference:true})` leaves absolute symlinks into the deleted staging dir (daemon then fails with ERR_MODULE_NOT_FOUND), pnpm's own links are relative and survive a verbatim copy.
- `@agents-office/shared` is a devDependency of desktop (it is inlined by esbuild), otherwise electron-builder tries to pack the workspace link. `npmRebuild: false`; there is no native module (node-pty is not a dependency yet); if one is added, add `asarUnpack` and revisit.
- Icon `resources/icon.png` is generated by `scripts/make-icon.mjs` (CC0, listed in `resources/LICENSES.md`, guarded by `test/packaging.test.ts`); the tray icon is still drawn at runtime.
- Packaged hook command verified: `ELECTRON_RUN_AS_NODE=1 release/linux-unpacked/agents-office resources/daemon/bin/agents-office.mjs hook` feeds the daemon. AppImage runs on this host with `APPIMAGE_EXTRACT_AND_RUN=1` (no FUSE needed); it extracts to /tmp/appimage_extracted_*.
- Desktop e2e lives in `e2e/desktop/` as the Playwright project `desktop` (`pnpm --filter @agents-office/e2e exec playwright test desktop`; `pnpm --filter @agents-office/e2e test` runs only the `web` project). It uses `release/linux-unpacked` if present else the dev app (`AGENTS_OFFICE_E2E_APP=dev|packaged`). Needs a display (xvfb-run on CI; xvfb is not installed on this host, XWayland was used).
- System notifications are only raised when the window is hidden or unfocused (`shell.ts`), so the e2e closes the window first. They are observed by patching `Notification.isSupported`/`Notification.prototype.show` through `app.evaluate`.
- macOS: the config (dmg, `identity: null`) and the CI job exist but nothing was run on macOS. `afterPack` has a darwin branch (`<Product>.app/Contents/Resources`) that is untested.
- `pnpm test` failed once (1 test, not reproducible in 3 reruns) when run right after other heavy work; looks like a timing flake, not related to this spec.

## Terminal ptys and IPC (spec 020)
- `node-pty` is `external` in `scripts/build.mjs` (native module, never bundled) and `asarUnpack: **/node_modules/node-pty/**` in `electron-builder.yml`; verified: packaged AppImage layout has `app.asar.unpacked/node_modules/node-pty/build/Release/pty.node` and the packaged e2e starts a pty. It works under Electron 44 without `electron-rebuild` (N-API); `npmRebuild: false` stays.
- Renderer API is `window.agentsOfficeDesktop.terminal` (type `TerminalBridge` in shared). `start` returns a union `{ok:true,id}|{ok:false,code,message}` (codes: claude-not-found, invalid-cwd, invalid-request, session-limit, spawn-failed) instead of rejecting, because `ipcRenderer.invoke` rewrites error messages ("Error invoking remote method..."). The `command` override of `SessionManager.start` is NOT in the zod schema (`.strict()`), so the renderer can never pick the binary; e2e uses the saved manual `claudePath` pointing to a fake script.
- Config (`<userData>/config.json`: `claudePath`, `maxSessions`, default 12, ceiling 64) lives in `appConfig.ts`; `setConfig` validates the path is absolute + executable and invalidates the resolver cache.
- An exited session is removed from `list()`/`getBuffer()` right away (the view must keep what it already received). Kill = SIGHUP, SIGKILL after `killGraceMs` (5 s); `before-quit` calls `killAll()` before stopping the daemon.
- `cleanClaudeEnv` keeps `CLAUDE_CODE_USE_*` and `CLAUDE_CODE_SKIP_*` (user provider choices); everything else `CLAUDECODE`/`CLAUDE_CODE_*`/`CLAUDE_EFFORT`/`CLAUDE_PID` is dropped.
- Live check on this host: `$SHELL -ilc` resolves `~/.local/bin/claude` in ~350 ms. The login PATH is merged into the pty PATH (claude's dir appended if absent). macOS/bash/fish remain unverified.
- Trust-folder dialog and auto/bypass modes (no PermissionRequest card) are documented in `permission-hook-and-pty.md`; the manager injects no input. The UI that shows this warning is a later spec.

## Terminal panel (spec 021, `packages/web/src/ui/terminalPanel.ts`)
- Pure model/logic in `ui/terminalTabs.ts` (tabs, titles `projeto · ativa|encerrada`, focus owner, panel height clamp, Ctrl+` and clipboard key mapping, `terminalBridgeOf`). The DOM + xterm view mounts only when `window.agentsOfficeDesktop.terminal` exists (`main.ts`); plain browser = no panel.
- Layout: `body` is a flex column, `#game` (flex:1) + `#ao-terminal`. `main.ts` computes the integer zoom from `#game`'s client size (not the window) and a `ResizeObserver` on `#game` calls `resize()`; the office keeps its whole zoom while the panel opens/collapses/drags.
- Sessions are adopted automatically: on mount `terminal.list()`, and when `onData` arrives for an unknown id (so spec 022 only has to call `terminal.start`; `panel.adopt(id)` exists too). History: `buffer(id)` then live data; events received before the buffer reply are dropped (they are inside the buffer because main appends before sending). Ids closed by the user go in a `closed` set so late output of a killed pty does not reopen the tab. Exited sessions vanish from `list()`, so after a window reload they are gone (the banner only lives in the renderer).
- Keyboard: terminal focus = xterm textarea focus; `onKeyboardOwner` sets `game.input.keyboard.enabled=false` and `resetKeys()` on every scene (the manager has no `resetKeys`). Clicking the canvas gives the keyboard back to the player, except a click inside the permission card while the terminal is focused: `mousedown.preventDefault()` keeps the textarea focus (card rect comes from `__office.permissions.cardRect`, game pixels). Focus is shown by the gold top border of the panel (terminal) or a gold inset frame on `#game` (player).
- xterm 6.0.0 + addon-fit 0.11.0 + addon-web-links 0.12.0 (pinned). CSS is imported from the panel module. `fit` -> `term.onResize` -> `terminal.resize`; a `lastCols/lastRows` guard avoids duplicate IPC.
- **Dev E2E serves the CLI's copy of the web build**: run the full `pnpm build` (not only `--filter web`) before desktop e2e in dev mode; the packaged mode needs `pnpm --filter @agents-office/desktop dist`.
- A fake claude that uses `trap ... WINCH` + `while read` dies on the first WINCH in dash (read is interrupted and returns non-zero). The panel fits the pty right after adopting a session, so fakes must loop with `while :; do read line && ...; done` and probe the size with an explicit command instead of a WINCH trap.
- E2E debug surface: `window.__terminalPanel` (tabs, collapsed, height, focus, keyboard, live `cols/rows`, `text()`, `paste()`); playwright's `toContain` prints trailing spaces as `·`.

## Project catalog and picker (spec 022)
- `src/main/projectCatalog.ts` (pure, fs-injectable): sources = cwds the web app passes in (`projects.list(known)`: the renderer already has the OfficeModel, the daemon has no HTTP route for it), the newest transcript per slug folder in `~/.claude/projects` (`AGENTS_OFFICE_PROJECTS_DIR` overrides, same var as the daemon), and `<userData>/projects.json` (favorites, recents max 30, folders added by hand; atomic tmp+rename, re-read before each write). Folders that no longer exist are dropped. Order: favorites, then used from the app (recents, newest first; a folder picked with "Novo projeto…" counts as just used), then the rest by transcript mtime.
- Slug = cwd with every non-alphanumeric char replaced by `-` (`/home/u/.claude` -> `-home-u--claude`); it is lossy, so `decodeSlug` walks the segments against the real directories (joiners `- . _ space`, empty token = dot-folder). Primary source for the cwd is the first `cwd` field in the head (64 KB) of the newest transcript.
- `terminal.start` gained `continueLast` (`--continue`; ignored when `resume` is set). Args order: `--permission-mode <m>` then `--resume <id>`/`--continue`. The picker always passes a mode (default `default`).
- Channels `agents-office:projects:*`, bridge `window.agentsOfficeDesktop.projects` (list/pickFolder/setFavorite/markUsed/sessions); renderer paths must be absolute. `dialog.showOpenDialog` runs in main; e2e stubs it with `app.evaluate(({dialog}) => { dialog.showOpenDialog = async () => ({canceled:false, filePaths:[x]}) })`.
- Web: pure logic `ui/projectPicker.ts` (filter, launch choice -> options -> claude args, mode labels with card support from spike 013: only `default` shows cards, `auto` does not; others labelled unverified), DOM in `ui/projectPickerPanel.ts` (button "Sessões" bottom-left next to "Hooks", `window.__projectPicker.open(cwd?)` for spec 023). While open it releases Phaser's keyboard via `onKeyboardCapture` (Phaser would `preventDefault` typed keys otherwise; do not copy settingsPanel's capture-phase `stopPropagation`, it would also block the search input).
- Never read the real `~/.claude/projects` in tests: fixtures only (temp dirs).
- Flake fix: the "SIGKILL a process that ignores SIGHUP" test now waits for the `HUP IGNORED` output and the exit event (the pty data event can land after `kill()` resolves under load).

# Tab <-> session binding and game actions (spec 023)

- Binding path: pty env `AGENTS_OFFICE_TERMINAL_ID` -> `agents-office hook` adds `terminalId` to the POST -> normalizer emits a separate `session.bound {sessionId, terminalId}` event (once per pair, only after `session.started` was emitted for the session) -> reducer sets `Session.terminalId`. It is its own event because the hook may come before or after the JSONL that starts the session; the reducer also tolerates `session.bound` before `session.started` (placeholder session keeps the field). External sessions never get the field, so "Abrir terminal" is derived purely from `session.terminalId !== undefined`. No cwd+time fallback was needed (env confirmed).
- Game side: `window.__desktopActions` (set in `main.ts` only with the terminal bridge) is the single switch for desktop-only actions: `openProjectPicker(cwd?)` and `openTerminal(id)` (-> `panel.focusSession`, expands a collapsed panel). The room door tile (front tile of the avatar, from the corridor or inside) opens the picker on the room's project; the Tech Lead dialog adds a `[T] Abrir terminal` page/prompt hint. E2E helper: `__office.actions.approachDoor(roomId)`.
- Tab titles: `projeto · ativa · <estado do escritório>` (`pensando`, `trabalhando`...), driven by `panel.setActivity(activityByTerminal(model))` on every model event.
- Latent bug fixed: `OfficeScene.ensureMap` destroyed the tilemap but left pending `reveals` pointing at its layers, so `updateReveals` threw (`reading 'width'`) on EVERY frame and froze the whole scene update (model in `__office` stale) when two rooms appeared close together. Reveals are now cleared when the map is recreated.
- Flake root cause of sessionManager "SIGKILL a process that ignores SIGHUP": the fake claude printed READY before installing its SIGHUP handler, so a kill right after READY terminated it with HUP (38 ms instead of the 300 ms grace). Handler now installed before READY.
- E2E fake claude can fire real hooks: `printf '{...SessionStart...}' | node packages/cli/bin/agents-office.mjs hook` inside the pty (needs `pnpm build` for cli/dist/hook.mjs); the port comes from the inherited `AGENTS_OFFICE_PORT`.

## External opener: VS Code (spec 024)
- `packages/desktop/src/main/externalOpener.ts`: discovery order is saved manual path (exclusive) -> login-shell PATH (`BinaryResolver.resolveLoginPath`) -> process PATH -> fixed locations (`/usr/bin`, `/snap/bin`, `/usr/local/bin`, flatpak exports; macOS app bundle CLI, then `open -a "Visual Studio Code" <dir>`). Everything runs with `spawn(file, argsArray)`, never a shell; the folder is one argv entry (absolute path, so it cannot look like a flag).
- This host has the REAL VS Code at `/snap/bin/code`: any test that reaches the fallback list with a real `run` would launch it. Tests either inject `isExecutable`/`run`, or use a fake `code` recording argv with `printf '%s\0' "$@"` and set it as the saved manual path (`external.setEditorPath`). The "not found" e2e writes a bogus `vscodePath` into `<userData>/editor.json` before launch instead of relying on an empty PATH.
- The manual path lives in `<userData>/editor.json` (`EditorPathStore`), separate from `config.json`; there is no settings UI field yet (bridge: `external.getEditorPath/setEditorPath`).
- `code` normally exits right after handing the folder to VS Code; `realRun` treats a process still alive after 8 s as success and detaches it.
- The Tech Lead dialog derives the VS Code folder from `model.projects[session.projectId].cwd` (Session has no cwd); `sessionActions(session, context, cwd)`.

## Session lifecycle: quit, tray, crash recovery (spec 025)
- Files: `main/quitFlow.ts` (`QuitCoordinator`, `buildQuitPrompt`), `main/sessionRegistry.ts` (`<userData>/sessions.json`: `active` while a pty runs, whatever is still `active` at the next start becomes `lost` and is offered by the web "lost sessions" box with `--resume <claudeSessionId>` or `--continue`), `main/main.ts` (wiring).
- Electron does NOT run Node's `process.on('SIGTERM')` in the main process: Chromium turns SIGTERM (and the session manager's logout) into a plain `app.quit()`, i.e. `before-quit`. So `before-quit` is "forced" (clean shutdown, no dialog, sessions stay recoverable) unless the quit was asked through the UI: tray "Sair" and the application menu "Sair" (Ctrl+Q / Cmd+Q, id `quit`) set `interactiveQuit` first. A test that calls `app.quit()` directly (or `electronApp.close()`) therefore takes the forced path; e2e triggers the interactive path with `Menu.getApplicationMenu().getMenuItemById('quit').click()`.
- A quit that ends the ptys deliberately removes them from the registry (nothing to resume); a forced one calls `registry.keepOnExitFromNow()` so the sessions it ends are offered again at the next start.
- `SessionManager` sweeps the process group with SIGKILL when the leader exits for ANY reason (not only on kill), otherwise a child that ignored SIGHUP outlives a session that ended by itself.
- E2E for kill -9: do NOT start the victim with `electron.launch`. SIGKILLing a Playwright-launched Electron leaves the `ElectronApplication` dangling (`app.close()` hangs, worker teardown times out after 90 s). The test spawns the app as a plain process with `--remote-debugging-port` and drives it with `chromium.connectOverCDP`, then SIGKILLs it and the orphaned Chromium helpers (found with `pgrep -f --user-data-dir=<sandbox>`).
- Manual verification with the real Claude Code on Linux/macOS was NOT done by the automated work (fakes only; no real `claude`/VS Code in tests). Checklist to run by hand: start a session from the picker, close the window (pty keeps running), reopen (buffer intact), tray Sair lists the sessions (project, active time) and Encerrar tudo leaves no `claude` children (`pgrep -af claude`), `kill -9` the app and relaunch (Retomar offered), `kill -TERM` (no dialog, sessions offered again).
- Flake root cause, `packages/daemon/test/hooks-cli.test.ts` "keeps the first backup...": each test spawns the CLI as a real process up to 5 times; under full-suite CPU load that exceeds vitest's 5 s default test timeout (not an assertion failure). The describe now has a 30 s timeout.
- Phaser can replay a queued `keydown-<KEY>` for the same DOM event when a key is pressed and released inside one frame (Playwright `keyboard.press`); `OfficeScene.setupInput`'s `press` helper ignores an event it already handled, otherwise "[V] Abrir no VS Code" ran `code` twice. A focused toolbar button also re-fires on Enter: e2e blurs `document.activeElement` before driving the dialog with the keyboard.
